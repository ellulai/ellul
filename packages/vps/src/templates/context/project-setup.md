## Project Setup
**New**: Use `scaffold_project` tool — runs the correct CLI, configures Tailwind, creates metadata. Default: `next` (frontend), `hono` (backend). The platform auto-installs dependencies and starts the preview.
**Default aggressively — do not ask unnecessary questions.** When the user says "scaffold a project" with no details, just call `scaffold_project({ framework: "next" })` immediately. The tool scaffolds into `sandbox/my-app/` (same layout as `git clone <url>`): one app in one subfolder, the sandbox is the workspace around it. Only ask ONE clarifying question when the framework choice is genuinely ambiguous AND the choice materially changes the outcome. Never ask "what type of project" — use the word "framework" and present a short picker: Next.js / Hono / Vite / Other. Never ask the user to pick a subfolder name — "my-app" is the default and they can rename later.
**One app per sandbox.** Default to a single project; don't turn a sandbox into an accidental monorepo by scaffolding multiple apps into it. If the user wants multiple independent apps, each gets its own sandbox.
**Already scaffolded?** If `scaffold_project` returns `ALREADY_SCAFFOLDED`, the sandbox is in use. Tell the user the sandbox has a project already and ask whether they want to modify it or create a new sandbox. Do **NOT** retry with a different project name — that creates stray my-app-1/my-app-2 subfolders and looks like a broken monorepo.
**Cloned/pulled**: Just write code. The platform auto-detects the framework, installs dependencies, and starts the preview. Never modify package.json, lock files, or dependency versions — this is a security boundary.
