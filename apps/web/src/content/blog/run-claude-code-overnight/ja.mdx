Claude Codeを夜通し走らせるパターンは、エージェント用ワークステーションの元を取る使い方です。23時に長時間タスク（6時間のリファクタ、モノレポ全体の依存関係アップグレード、テストスイートの移行）を投入し、ノートPCを閉じて寝て、朝起きるとパスキー承認を待つドラフトPRが届いています。あなたが不在の間に8時間分のエンジニア工数が生まれるわけです。

これは実用的なウォークスルーです。Claude Codeを無人で走らせる設定、特権アクションをパスキーゲートに通す方法、そして午前3時に実際に発生する3つの障害モードを扱います。コストについても率直に説明します。モデル料金、ワークステーションの月額、そしてどの時点で計算が成り立たなくなるかを含めて。

Claude Code自体の背景については [/agents/claude-code](/agents/claude-code) のページがエージェントの特性をカバーしています。より広いカテゴリについては、[常時稼働AIエージェントの柱ページ](/concepts/always-on-ai-agent) と [長時間稼働エージェントの用語集](/glossary/long-running-agent) が標準的な参照先です。

## なぜ夜通し走らせる価値があるのか

夜通し走らせて最も恩恵を受ける作業は、付きっきりで監視するのが苦痛な作業です。実務でよく見る3つのパターンがあります。

長時間のリファクタリング。あるパターンを別のパターンに変換するためにコードベースを4〜8時間かけて通すケース。ホットパスのリネーム。テストフレームワークの移行。依存関係をフォークに置き換える作業など。エージェントが80%を自律的に処理し、残りの20%は朝に人間の目が必要になります。

依存関係アップグレードのパス。「CVEがあるマイナーバージョンをすべてアップグレードし、それぞれテストスイートを実行し、パッケージごとにPRを開いて」といった作業。停止条件が明確な長時間タスクであり、まさに無人実行に向いています。

テストスイートの移行。MochaからVitestへ、JestからVitestへ、RSpecからMinitestへの切り替え。エージェントがバッチ単位でテストを書き換え、移行したバッチを実行し、失敗を修正し、チャンクごとにPRを開きます。

夜通しに向かない形は、1回の悪手で取り返しがつかなくなる作業です。後でこの点に戻ります。ランタイムが適切に設定されていれば、取り返しのつかない事態を実行中に止めることもできます。

## ノートPCのスリープ問題

ノートPCではこれが難しい理由を、念のため明示しておきます。ノートPCはスリープします。Claude Codeはあなたのシェルで動くプロセスです。ノートPCがスリープするとプロセスは中断されます（電源設定によっては終了されます）。ノートPCを起こすとプロセスは中途半端な状態から再開するか、もしくは死んでいます。どちらも「6時間作業が続いた」状態ではありません。

ネットワークの変化が問題を複雑にします。カフェのWiFiから自宅のWiFi、そしてスマホのテザリングへ。それぞれの切り替えで、エージェントのAPI呼び出し、MCPサーバー接続、シェルセッションが切断される可能性があります。Claude Codeはリトライしますし、モデルAPIもリトライします。「3回のネットワーク切り替えを挟んで6時間動き続けるエージェント」の累積信頼性は、「安定接続上で6時間動くエージェント」と比べてはっきりと低くなります。

解決策はエージェントをノートPCから外すことです。永続的な場所ならどこでも構いません。自宅にあるLinuxマシン、クラウドVM、専用ワークステーションなど。私たちは [Ellulのエージェント・ワークステーション](/concepts/agent-workstation) を使っていますが、これは私たちが作ったからであって、原則は永続ランタイム全般に当てはまります。

## ウォークスルー

常時オンのLinuxマシンが必要です。セルフホスト、クラウドVM、または [Ellulのワークステーション](https://console.ellul.ai/sign-up) のいずれか。Ubuntu 24.04 LTS、`~/work/repo` にクローンしたリポジトリ、`$PATH` にインストール済みの `claude`、そしてパスキー承認を受け取る手段（スマホ、ハードウェアキー、登録済みのノートPC）を前提とします。

Ellulでは、これは「ワークステーションを作成し、サンドボックスをGitHubリポジトリに向け、エージェントピッカーからClaude Codeをインストール」する流れになります。セットアップには [Sovereign Shield](/glossary/sovereign-shield) とパスキーゲートがすでに組み込まれた状態で出荷されます。

### 無人実行用にClaude Codeを設定する

重要なフラグは2つです。

<CodeTabs>

```bash
# 無人運用の積極的な側。エージェントは特権でない確認では
# 一時停止しません。ランタイムが特権アクションをプロセス外で
# すでにゲートしている場合にのみ使用してください。
claude code \
  --dangerously-skip-permissions \
  "refactor src/auth to use the new TokenProvider pattern from the design doc"
```

```bash
# 保守的な側。エージェントは不確実なアクションで一時停止します。
# 夜通し実行を初めて試すときはこちらが向いています。
claude code \
  --max-turns 200 \
  "refactor src/auth to use the new TokenProvider pattern from the design doc"
```

</CodeTabs>

`--dangerously-skip-permissions` フラグの命名には理由があります。プロセス外の特権アクションゲートを持たないランタイムでは、名前のとおり危険そのものです。git push・デプロイ・シークレット読み取りがエージェントのプロセス外でゲートされているランタイムなら、このフラグは安全になります。エージェントはファイル編集とテスト実行を中断なく走らせ、特権が必要な箇所でゲートに到達して止まります。これが設計上の眼目です。

### タイムアウトと予算で実行をラップする

二重の安全策です。ラッパースクリプト。

```bash
#!/usr/bin/env bash
set -euo pipefail

cd ~/work/repo

# 8時間の壁時計上限。
timeout 8h \
  claude code \
    --dangerously-skip-permissions \
    --max-turns 400 \
    "$@"

# 常にexit 0。timeoutの終了コード124は失敗ではなく
# 想定どおりの停止として扱います。
exit 0
```

これを `~/run-overnight.sh` として保存します。`timeout 8h` が壁時計のガードで、`--max-turns 400` がエージェントの内部ステップ上限です。どちらかが発動すると実行はクリーンに終了します。これらがないと、ループにハマったエージェントがあなたの就寝中にモデル予算を全部燃やし切る可能性があります。

### 寝る前に実行を投入する

ワークステーションに接続し、切断後も生き残る長時間セッションでエージェントを起動します。

<CodeTabs>

```bash
# tmuxで永続セッション。Ctrl+bのあとdでデタッチします。
ssh agent.workstation
tmux new -s overnight
~/run-overnight.sh "upgrade all minor versions in package.json with CVE coverage, run the test suite for each, open a PR per package"
# Ctrl+b dでデタッチ
```

```bash
# またはワークステーション内蔵のエージェントUI経由で。
# （Ellulではチャットパネルがブラウザタブを閉じても生き残る
# 永続ネームスペース内でエージェントを実行します。）
```

</CodeTabs>

Ellulを使っている場合、チャットパネルが代わりに処理してくれます。エージェントは永続ネームスペース内で動くので、ブラウザタブを閉じてもエージェントは止まりません。

### パスキーゲートでの承認とともに目覚める

エージェントが夜通し働きます。すべての特権アクション（`git push`、`vercel deploy`、`pnpm publish`、シークレット読み取り）は [パスキーゲート](/glossary/passkey-approval) で一時停止します。あなたが起きると、スマホやノートPCに通知が届いています。

- 「Claude Codeがブランチ `auth-refactor` をoriginにpushしようとしています。承認しますか？」
- 「Claude Codeがシークレット `STRIPE_SECRET_KEY` を読み取ろうとしています。承認しますか？」
- 「Claude Codeがstagingにデプロイしようとしています。承認しますか？」

それぞれをTouch IDまたはFace IDでタップします。アクションが進みます。PRが開きます。デプロイが行われます。エージェントが完了します。

エージェントが想定外のことをしていれば、ゲートが捕まえています。想定外の要求を確認し、拒否し、監査ログを読んでなぜエージェントがそこに至ったかを調べられます。

## コストモデル

先週実際に走らせた夜通し実行の数字を使った、率直な会計です。

モデル料金。Anthropic API価格で、コンテキストを積極的に読む8時間のClaude Code実行は通常$5から$30の間に収まります。差はおもにプロジェクトの規模と、エージェントがファイルを再読み込みする頻度によります。50k LOCのリポジトリ上の中規模リファクタは$15あたり。200パッケージのモノレポでの「マイナーバージョン全アップグレード」パスは$30に近づきます。

ワークステーション。Ellulの個人プランで月$20、プロで月$50。どちらも24/7稼働なので、ワークステーション代は夜通し実行の回数によらず月額固定です。週3回の夜通し実行なら、1回あたりおよそ$1.50から$4にならされます。

合計。典型的な夜通し実行は総額$7から$35です（モデル料金にならされたワークステーション代を加えた額）。日中であれば4〜8時間のエンジニア工数を要する作業を生み出します。ジュニアエンジニアの賃金で計算しても、ほぼ即座に元が取れます。シニアエンジニアの賃金なら、比較になりません。

計算が成り立たなくなる場合。夜通し実行が継続的に有用なPRを生み出せない場合（エージェントが脱線する、検証ステップが弱い、アップグレード対象の依存関係が各ステップで人間の入力を要する場合など）、あなたは負の出力に対してモデルトークン代を払っていることになります。直し方はパターンを捨てることではなく、検証とタスクスコープを改善することです。私たちの観測では、夜通し実行のおよそ80%が有用なPRを生み、20%は朝に再プロンプトが必要です。

## 午前3時の障害モード

実際に起こる3つのこと、検出と修正の方法とともに。

<Callout variant="warn" title="APIレート制限">
エージェントがAnthropicの分単位レート制限を使い切り、バックオフでリトライを始めます。実行は続きますが速度が極端に落ちます。検出方法：エージェントの進捗出力に長い停止が現れ、合計実行時間が8時間の上限を超えていきます。修正方法：Anthropicでより高いレート制限ティアを契約するか、別々のワークステーション上の複数エージェントに作業を分割します（それぞれが独自のレート制限プールを持ちます）。
</Callout>

<Callout variant="warn" title="OOM">
長時間動くClaude Codeセッションは最終的に状態を蓄積していきます。小さなワークステーション（1〜2GB RAM）では、長時間実行がOOMに到達してエージェントが落ちることがあります。検出方法：タイムアウト前にクリーンな終了なしで実行が死んでいます。修正方法：より大きなワークステーション（ほとんどの夜通し実行で4GB以上が快適）、または中間チェックポイントを挟んで作業を短いセッションに分割します。
</Callout>

<Callout variant="warn" title="無限ループ">
エージェントが解けない問題に詰まり、同じアプローチを永遠に繰り返します。検出方法：進捗出力に反復的なサイクルが現れ、エージェントが検証ステップに到達しません。修正方法：`--max-turns` の上限（私たちは8時間実行で400、短いものではより低く設定します）、加えて最後の砦としてのタイムアウト上限。監査ログには上限到達時にエージェントが何をしようとしていたかが残るので、朝により多くの文脈とともに再プロンプトできます。
</Callout>

3つすべてを捕まえるのは、明示的な上限を持つラッパー＋プロセス外ゲートを持つランタイムの組み合わせです。上限が暴走エージェントを止め、ゲートが意図しないアクションを止めます。どちらも欠けると、夜通し実行はルーレットになります。

## 夜通し実行が適切な道具でないとき

率直に言って、夜通し実行は明確な停止条件と許容できるリトライコストを持つタスクに向いています。本番クリティカルなホットフィックス（人間をループに含めたい）、実行中に人間の判断を要するタスク（「2つのリファクタアプローチのうち優れた方を選ぶ」にはあなたが必要）、新規のエージェントセットアップ（プロジェクトでClaude Codeを初めて試すときは日中に走らせる）には向きません。

向く形は「リスクが低く、スコープが明確で、検証可能」なものです。エンジニアリング作業の多くを占めますが、すべてではありません。
