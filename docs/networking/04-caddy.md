# Caddy

The reverse proxy on every VPS. mTLS-validated by Cloudflare in proxied mode; ACME-validated by Let's Encrypt in direct mode.

Caddyfile is generated by `caddy-gen`, source `packages/vps/src/services/gateway/caddy-gen/caddyfile.ts` and `handlers.ts`.

## Generation inputs

```typescript
interface CaddyfileOptions {
  deploymentModel: 'proxied' | 'direct';
  mainDomain: string;     // <id>-srv.ellul.ai
  codeDomain: string;     // <id>-code.ellul.ai
  devDomain: string;      // <id>-dev.ellul.app
  platformZone: string;   // ellul.ai
  appZone: string;        // ellul.app
  consoleOrigin: string;  // https://console.ellul.ai
  customDomain?: string;
  originTag?: string;
  canDeploy?: boolean;
}
```

Sources at runtime (`caddy-gen/main.ts:56-98`):

- `--model`, `--main-domain`, etc. — CLI args.
- `/etc/ellul/platform-zone`, `/etc/ellul/app-zone`, `/etc/ellul/console-origin` — vault-bound text files.
- `/etc/ellul/custom-domain` — optional.
- `/etc/ellul/origin-tag` — optional but required for proxied mode SNI.

## Proxied mode site blocks

```caddy
# AI zone (platform services + main domain)
{$MAIN_DOMAIN}:443, {$CODE_DOMAIN}:443, o-{$ORIGIN_TAG}.ellul.ai:443 {
  tls /etc/caddy/origin.crt /etc/caddy/origin.key {
    client_auth {
      mode require_and_verify
      trusted_ca_cert_file /etc/caddy/cf-origin-pull-ca.pem
    }
  }
  
  # Restore Host from X-Forwarded-Host (Worker added it)
  @has_xfh header X-Forwarded-Host *
  handle @has_xfh {
    rewrite (preserves Host for matchers below)
  }
  
  @code host {$CODE_DOMAIN}
  @main host {$MAIN_DOMAIN}
  
  # ... handlers ...
}

# App zone (preview, deployed apps; wildcard)
*.ellul.app:443 {
  tls /etc/caddy/origin-app.crt /etc/caddy/origin-app.key {
    client_auth {
      mode require_and_verify
      trusted_ca_cert_file /etc/caddy/cf-origin-pull-ca.pem
    }
  }
  
  @app host {$DEV_DOMAIN}
  
  # ... handlers ...
}

# Custom domain (optional)
{$CUSTOM_DOMAIN}:443 {
  tls /etc/caddy/origin.crt /etc/caddy/origin.key {
    client_auth { ... }
  }
  
  # Rewrite to mainDomain handlers
}
```

The origin hostname `o-<tag>.ellul.ai:443` is critical for proxied mode. SNI from CF will be `o-<tag>...`; without that hostname in the addresses, Caddy's strict SNI denies with 421.

## Direct mode site block

```caddy
{$MAIN_DOMAIN}, {$CODE_DOMAIN}, {$DEV_DOMAIN} {
  # auto_https on (default)
  # ACME with HTTP-01 or DNS-01 challenge
  
  # All handlers in single block
  @code host {$CODE_DOMAIN}
  @main host {$MAIN_DOMAIN}
  @dev host {$DEV_DOMAIN}
  
  # ... handlers ...
}
```

No mTLS. Single zone (no .ai vs .app split). Simpler.

## Forward auth

```caddy
@protected not path /_auth/login* /_auth/register* /_auth/recovery*
forward_auth @protected 127.0.0.1:3005 {
  uri /_auth/session
  header_up Cookie {http.request.header.Cookie}
  header_up X-PoP-Signature {http.request.header.X-PoP-Signature}
  header_up X-PoP-Timestamp {http.request.header.X-PoP-Timestamp}
  header_up X-PoP-Nonce {http.request.header.X-PoP-Nonce}
  header_up X-PoP-BodyHash {http.request.header.X-PoP-BodyHash}
  header_up X-Forwarded-Method {method}
  copy_headers X-Auth-User X-Auth-Tier X-Auth-Session X-Auth-Timestamp X-Auth-HMAC
}
```

Caddy makes a sub-request to Shield's `/_auth/session`. Shield validates and returns 200 + auth headers (or 401). Caddy decorates upstream request with the headers.

For PoP details: [../security/04-passkey-and-pop.md](../security/04-passkey-and-pop.md).

## Handlers

`packages/vps/src/services/gateway/caddy-gen/handlers.ts:273-350+`.

### Shield direct (no auth)

```caddy
handle /_auth/login* /_auth/register* /_auth/recovery* /_auth/bridge {
  reverse_proxy 127.0.0.1:3005
}
```

These endpoints serve login/register/recovery flows that, by definition, run before auth. No forward_auth.

### File API

```caddy
handle @code {
  reverse_proxy 127.0.0.1:3002 {
    flush_interval -1   # WebSocket support
  }
}
```

### Agent Bridge

```caddy
handle @main /ws {
  reverse_proxy 127.0.0.1:7700 {
    flush_interval -1
  }
}
```

### Term Proxy

```caddy
handle /term/* {
  reverse_proxy 127.0.0.1:7701 {
    flush_interval -1
  }
}
```

### App preview (per-deployed-app)

For deployed apps, Caddy imports per-app site blocks:

```caddy
import /etc/caddy/sites-enabled/*.caddy
```

Each `<sandboxId>.caddy` file contains a site block specific to one app:

```caddy
{$CUSTOMER_APP_DOMAIN}:443 {
  tls /etc/caddy/origin.crt /etc/caddy/origin.key {
    client_auth { ... }
  }
  reverse_proxy 127.0.0.1:4012  # this app's PM2 port
}
```

Written by Sovereign Shield when the user approves a `deploy` gate.

## CORS headers

```caddy
header ?Access-Control-Allow-Origin "{$CONSOLE_ORIGIN}"
header ?Access-Control-Allow-Credentials "true"
header ?Access-Control-Allow-Methods "GET, POST, DELETE, OPTIONS"
header ?Access-Control-Allow-Headers "Content-Type, Authorization, Cookie, X-Code-Token, X-PoP-Signature, X-PoP-Timestamp, X-PoP-Nonce"
```

The `?` modifier sets the header only if not already present (preserves app-generated CORS).

## Static unauthorized page

For unauthenticated requests (forward_auth returned 401), Caddy serves a friendly page from `/var/www/ellul/index.html` (root:root 644).

## Reload mechanism

Configuration reloads via Unix socket admin API:

```bash
sudo /usr/bin/caddy reload --address unix//run/caddy/admin.sock
```

`/run/caddy/admin.sock` is `caddy:caddy 2770`. Only services in `caddy` group (Sovereign Shield via SupplementaryGroups) can connect.

Reload is fast (<1s) and config-validated before swap. Downstream connections aren't dropped.

## Cert lifecycle

### Proxied mode

- `/etc/caddy/origin.crt` and `/etc/caddy/origin.key` — Cloudflare-issued for `*.ellul.ai`.
- `/etc/caddy/origin-app.crt` and `/etc/caddy/origin-app.key` — for `*.ellul.app`.
- `/etc/caddy/cf-origin-pull-ca.pem` — Cloudflare's AOP CA for client cert validation.

Provisioned at first boot; updated when API rotates origin certs.

### Direct mode

ACME challenge response managed by Caddy. Certs cached in `/var/lib/caddy/`.

For ACME, port 80 must be reachable from public internet (HTTP-01) or DNS API access (DNS-01).

## Validation before reload

`caddy validate --config /etc/caddy/Caddyfile.new` runs before swap. Bad configs don't make it live.
